Training lab: ml/train.py

Click a step on the left, then open Double-click details on each screen. Data comes from a real encode_example run on ml/data/sample/train.jsonl (smoke tokenizer).

Steps

Big picture

train.py reads chat JSONL, builds a small tokenizer, turns each row into numbers, and updates a tiny GPT-2 so it predicts assistant tokens (shell output) given the conversation so far.

tiny.yaml + train.jsonl → train.py → ml/outputs/…
Inputs
  • Config: ml/config/tiny.yaml
  • Train / val JSONL (--smoke → ml/data/sample/)
  • Flags: --max-steps, --output-dir
Outputs
  • model.safetensors — weights
  • tokenizer.json — text ↔ IDs
  • config.json, train_meta.json
Double-click details — what is “training” here?

This is supervised causal language modeling. Each JSONL line is a full conversation. The model is not told “run bash”; it learns statistics of token sequences that look like <|user|> … command followed by <|assistant|> … output.

Parameter
A number inside the network that training adjusts (~3.4M of them).
Step
One batch processed and one optimizer update (AdamW).
Smoke mode
--smoke uses the small committed sample and faster hyperparameters for CI.

            Before training, train.py fits byte-level BPE on all message text in train+val files

            Double-click details — BPE & special tokens
            

              

                BPE merges frequent character pairs into subword tokens until the vocabulary reaches the
                target size. Byte-level means it can represent any UTF-8 text.
              

              
Reserved markers: <|system|>, <|user|>, <|assistant|>, <|end|> — must stay single tokens after training the BPE.

              
Code: train.py → build_tokenizer(), iter_message_text().

            

          

        


        
        

          
Step 3 — encode_example (ml/chat_format.py)

            Double-click details — why -100?
            

              

                Hugging Face uses label -100 to mean “do not compute loss at this position.” We already know the
                system prompt and user command; we only want the network to learn to continue with assistant text
                and <|end|>.
              

              
Output dict per row: input_ids, labels, attention_mask (all 1s until padding).

              
Code: EncodedChatDataset in train.py calls encode_example for each JSONL line.

            Double-click details — causal LM
            

              

                At each position, the model may only attend to earlier tokens (causal mask). It outputs a
                probability distribution over the vocabulary for the next token. Training compares that distribution to the true next token (cross-entropy).
              

              
train.py checks parameter count is between 1M and 10M (~3.35M for this config).

            

          

        


        
        

          
Step 5 — Batch & pad (PadCollator)

          

            The Trainer groups several examples into a batch. Shorter sequences are padded so all rows have the same width.
          

          

            
Mini example (batch size 2)

            

          

          

            Double-click details — tensors
            

              

                
input_ids

                
Padded with pad_token_id (here, end-of-text token).

                
labels

                
Padded with -100 so loss ignores pad positions.

                
attention_mask

                
1 on real tokens, 0 on pad — model must not attend to pad.

              

              
Code: PadCollator in train.py → PyTorch torch.Tensor batches.

            

          

        


        
        

          
Step 6 — One training step

          
Inside trainer.train(), each step: forward → loss → backward → AdamW update. CPU only in this repo (use_cpu=True).

          

          

            Double-click details — forward / backward
            

              
Forward: batch input_ids → model → logits shape [batch, seq, vocab].

              
Loss: only positions where labels ≠ -100.

              
Backward: gradients flow to all parameters that influenced those predictions.

              
Optimizer: AdamW nudges weights to reduce average loss.

            

          

        


        
        

          
Step 7 — Trainer loop

          

            Repeats for max_steps (500 smoke / 1500 full). Periodically runs validation loss on val.jsonl.

            Double-click details — TrainingArguments
            

              
Key settings in train.py: learning_rate, warmup_steps, lr_scheduler_type (cosine or constant for smoke), per_device_train_batch_size=4, save_strategy=no (single save at end).

              
GitHub Actions: PR runs --smoke --max-steps 10; push to main runs full data + upload to Hub.
